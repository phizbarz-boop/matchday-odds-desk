Auto Builder and booking-code analysis now opt into background read-only jobs. POST returns HTTP 202 immediately; the browser polls a same-origin status URL through short requests. This avoids keeping the entire scan inside one proxy request. Existing API callers without the opt-in header retain synchronous behavior. One active background scan per process limits overlapping load; busy responses are explicit JSON. Jobs have a four-minute abort deadline, ten-minute result retention, and explicit restart/expiry errors. Empty, malformed and non-object responses show clear errors instead of JSON.parse exceptions. The browser never starts a booking until it receives valid completed selections. No scan or booking is automatically resubmitted. Scans can still fail if SportyBet is unavailable or the host restarts; those failures now have a visible result.
