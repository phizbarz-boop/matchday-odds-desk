# Regeneration and Telegram analyzer updates

After a website booking code appears, 'Regenerate different ticket' scans current odds again using the saved Auto Builder settings. Probability, edge, sports, selected markets, extra-market toggle, dates and selection limits remain the same. If the previous auto ticket reached its target, the regenerated ticket must also reach that target. Different outcomes, bet types or fixtures may be selected. The signature includes event, market, outcome and specifier; reordering or changing odds does not count as a new variation.

Website ticket signatures and last settings are retained in this browser's local storage. The API rejects excluded selection sets before returning a variation; the bounded search reports 'No other ticket variation was found with the same probability model and settings' when it finds none. This does not prove no mathematical combination exists outside the search frontier. Clearing browser storage or using another browser resets its website history. Manually chosen slips use current Auto Builder settings when no prior auto request is available. History requests over 2,000 signatures are rejected rather than silently dropping exclusions.

Telegram Elite users have an Extra prematch markets ON/OFF switch in Builder → Bet Types. It enables the same bounded extra-market scan and labelled probability models as the website; SAFE and lower-plan curated market permissions retain their existing restrictions. Rebuild keeps the prior settings and excludes selection signatures retained with the Telegram user in persistent Redis. No alternate result must reuse an excluded selection set after live validation.

Both website and Telegram code analysis request additional supported markets, including imported fixtures without a kickoff timestamp; fresh public details must confirm they are upcoming. Known event/market/outcome/specifier identifiers must match exactly so another market on the same fixture cannot be wrongly reported as the original selection's model.

Telegram analysis results now include 'Generate Qualified Ticket'. This explicit action reruns analysis using the saved threshold, horizon and live opt-in, then books only selections that are still qualified. It rejects empty tickets, repeated fixtures, exceeding the plan/40-game cap, unavailable sports and already generated selection sets. Successful generation consumes one ticket credit, not an extra analysis credit, and returns code and combined odds. Replace Unsupported remains an explicit action; its choice is retained for subsequent generation. Private generated codes are sent to that user rather than published to the channel.

All new market support is subject to the coverage limitations documented in EXPANDED-MARKET-COVERAGE.md. Unknown partitions and unmodeled specialty live settlement rules remain unsupported.
