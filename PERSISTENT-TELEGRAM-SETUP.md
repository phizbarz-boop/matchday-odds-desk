# Memberships, ticket history and schedules

Set REDIS_URL on Render to a Redis database with durable storage, no automatic expiration of the database, and a no-eviction policy for membership records. Keep the same database across deployments. Render Free Key Value is memory-only and loses its contents on restart; this app cannot recover data deleted by that provider. Local files and server memory on a free Render web service are also temporary.

Membership activation now refuses to report success without Redis. Membership entitlements have a separate, non-expiring record so an older bot preference save cannot overwrite a newer activation. Existing paid user records continue to work. If a previous restart already erased a member, an administrator must activate that member again after configuring persistent storage.

Today's Codes appends each shared channel code to a per-day Redis hash keyed by booking code, retaining earlier runs and deduplicating repeated saves. SAFE, next-12-hour, hourly Live/QC and website Send to Telegram codes are included. Personal builder codes sent privately to an individual are not published to other members. Legacy scheduled-code storage remains readable. Daily history is retained without a time-to-live; administrators should archive/delete old daily hashes when appropriate.

Next-12-hour prematch picks use the probability model, all six supported sports and all currently modeled market families, without the SAFE batch's restricted market list. Every selection has an 80% full-winning-probability floor. The 10,000x, 2,500x and 500x targets may use a 75% fallback if the bounded search cannot reach the target at 80% with the match-and-bet-type separation rules. The three 100x variations never fall below 80%. A fresh public scan rechecks model probabilities and offered selections before booking. Unsupported SportyBet markets cannot be given a trustworthy probability by the current model and are not included. Exhaustive coverage of every SportyBet specialty market is not implemented by this change. No combination is guaranteed safe or guaranteed to reach its requested target; unreachable targets are skipped.

The app schedules remain primary. GitHub Actions now also request hourly picks at :08 UTC and next-12-hour picks at 06:05 and 17:05 UTC (07:05 and 18:05 WAT), using the same scheduled slots and Redis locks to avoid duplicate sends. Ensure Actions is enabled and TELEGRAM_JOB_SECRET is the same GitHub secret and Render environment value. Optional GitHub variable MATCHDAY_BASE_URL points to the Render URL. Manual runs retain their separate request IDs.

A scheduled request can wake a sleeping Render service; it cannot guarantee precise timing. GitHub cron may be delayed or disabled, and free hosting quotas still apply. A timer or self-refresh inside a sleeping process cannot wake that process. Free Render services idle after 15 minutes, and restarting can happen at any time. For reliable continuous scheduling, move the worker to an always-running host or a managed scheduler; this update provides best-effort free wake-up requests, not a guarantee of uninterrupted uptime.

Install the downloaded archive over the existing repository while preserving .git, .env files, node_modules and local data, then commit and push to trigger your usual Render deployment. This archive does not configure your external database or deploy itself.

Different matches can freely use the same bet type across slips. On the same match, a different bet type is also allowed across slips. Reusing the same match and bet type requires the exact same selection to have at least 90% full-winning model probability, with a maximum of three tickets. Each ticket still has at most one selection per match and the three 100x variants cannot be identical.

## Additional hockey/tennis batch every three hours

At 00:00, 03:00, 06:00, 09:00, 12:00, 15:00, 18:00 and 21:00 WAT, the app scans fresh public SportyBet prematch markets for the next 12 hours and tries to create three different 100-odds slips. Each slip is entirely ice hockey or entirely tennis. The model compares the estimated combined winning probability of bounded candidate combinations from each sport and chooses the stronger available combination; there is no minimum per-game probability or edge floor beyond valid modeled probabilities. A 100-odds target is not guaranteed. Each slip has at most 40 selections and no repeated match; matches cannot repeat among the three variations, regardless of model rating.

Matches reserved by this batch remain blocked at later three-hour slots until a SportyBet selection settlement is confirmed. Missing results, unavailable feeds and uncertain bookings remain blocked; three hours passing never releases them. These reservations and per-slip send checkpoints persist in Redis. Prepared codes can retry delivery; uncertain Telegram sends cannot automatically resend. Reservations apply across this additional batch's runs, not to the separate next-12h or live/QC products. Codes are appended to Today's Codes, and tickets join the existing settlement/ROI tracking.

Set TELEGRAM_THREE_HOURLY_ENABLED=false to disable the new batch (default true). GitHub workflow 'Plot207 Hockey Tennis Every Three Hours' provides an external wake-up request at :12 after each slot; its endpoint is /api/telegram/three-hourly-picks and uses the existing TELEGRAM_JOB_SECRET. Both manual and scheduled requests share the current three-hour slot, so repeated requests cannot duplicate the batch. GitHub/Render free scheduling remains best effort.
